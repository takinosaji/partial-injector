# spinq Test Package — Design

**Date:** 2026-08-14
**Status:** Approved

## Problem

`spinq` is the only publishable package in the workspace without a test package. Its 25 helpers
(21 in `lists.py`, 4 in `dicts.py`) are pure functions with documented raise-paths, none of which
is currently verified. The workspace has no CI, so an untested package is untested everywhere.

## Scope

Additive only. No change to `src/spinq/spinq/*.py`, therefore no `spinq` version bump and no
`CHANGELOG.md` entry.

## Package scaffolding

New uv workspace member at `tests/test-spinq`, modeled on the existing `tests/test-sversion`.

```toml
[project]
name = "spinq-tests"
version = "0.0.0"
description = "spinq unit tests"
license = { text = "MIT" }
authors = [{ name = "Kostiantyn Chomakov", email = "kostiantyn.chomakov@gmail.com" }]
requires-python = ">=3.14,<3.15"
dependencies = ["pytest>=8.3.5", "spinq"]

[tool.uv.sources]
spinq = { workspace = true }

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[tool.hatch.build.targets.wheel]
packages = ["test_spinq"]
```

- No `faker`: literal data is clearer than generated data for pure functions.
- No `pytest-asyncio`: nothing in `spinq` is async.
- `[tool.ruff]` and `[tool.pytest.ini_options]` blocks are copied verbatim from
  `tests/test-sversion/pyproject.toml`, per the workspace convention that each member duplicates
  the root ruff config. `known-first-party` in the member file is `["spinq", "test_spinq"]`;
  `testpaths` is `["test_spinq"]`.

## Test layout

Folder per source module, file per functional category. Every one of the 25 functions appears in
exactly one file.

```
tests/test-spinq/test_spinq/
├── __init__.py
├── test_lists/
│   ├── __init__.py
│   ├── test_case_lookup.py
│   ├── test_case_filtering.py
│   ├── test_case_projection.py
│   ├── test_case_set_ops.py
│   ├── test_case_sorting.py
│   └── test_case_quantifiers.py
└── test_dicts/
    ├── __init__.py
    ├── test_case_lookup.py
    └── test_case_indexing.py
```

`distinct_` belongs to `test_case_set_ops.py` (not filtering) because it is set-based.
`where_` belongs to `test_case_filtering.py` alongside `filter_`, of which it is an alias.

## Coverage

Depth per function: a matching case, a no-match case, an empty-input case, and each documented
raise. Total ≈ 97 tests.

### `test_lists/test_case_lookup.py` — 7 functions

`first_`, `first_or_none_`, `first_or_none_with_index_`, `last_`, `last_or_none_`, `single_`,
`single_or_none_`

- Returns the correct element for a matching predicate; `first_` vs `last_` distinguished by a
  list with two matches.
- `first_`/`last_` with no match and on `[]` raise `ValueError("No elements match the predicate.")`.
- `first_or_none_`/`last_or_none_` return `None` in those cases.
- `first_`, `first_or_none_`, `first_or_none_with_index_`, `last_`, `last_or_none_` called
  without a predicate use the `lambda x: True` default and return the head/tail.
- `first_or_none_with_index_` returns `(index, element)` with the index of the match, not of the
  filtered result.
- `single_` raises `ValueError("No elements match the predicate.")` on zero matches and
  `ValueError("More than one element matches the predicate.")` on two or more.
- `single_or_none_` returns `None` on zero matches, still raises on two or more.
- `single_`/`single_or_none_` take a required predicate — no default-predicate test.

### `test_lists/test_case_filtering.py` — 4 functions

`filter_`, `where_`, `without_`, `except_`

- `filter_` keeps matching elements in their original relative order; no match → `[]`; `[]` → `[]`.
- `where_` returns the same result as `filter_` for the same input (alias contract).
- `without_` returns the exact complement of `filter_` for the same predicate.
- `except_` removes every occurrence of each excluded value, including duplicates, and preserves
  the order of what remains; an empty exclusion list returns an equal list.

### `test_lists/test_case_projection.py` — 3 functions

`select_`, `select_many_`, `where_with_index_`

- `select_` applies the selector to every element and preserves order and length; `[]` → `[]`.
- `select_many_` flattens exactly one level; inner empty lists contribute nothing; `[]` → `[]`.
- `where_with_index_` returns `{index: element}` keyed by position in the original list, skipping
  non-matching positions; no match → `{}`.

### `test_lists/test_case_set_ops.py` — 2 functions

`union_`, `distinct_`

- Assertions are order-independent (`sorted(...)` or `set(...)`), because both docstrings state
  the result order is not guaranteed. Asserting exact list order would couple the tests to
  CPython set iteration order.
- `distinct_` removes duplicates; a list already distinct is returned with the same members;
  `[]` → `[]`.
- `union_` yields the distinct union; disjoint, overlapping, and empty-operand cases.
- Both raise `TypeError` on unhashable elements (e.g. `[[1], [2]]`) — asserted as `TypeError`
  without a message match, since the message comes from CPython.

### `test_lists/test_case_sorting.py` — 2 functions

`order_by_`, `order_by_descending_`

- Sorts by the value returned from the key selector, not by the element itself (use a list of
  tuples or objects so the two differ).
- `order_by_descending_` is the reverse of `order_by_` for the same input.
- Neither mutates its input — assert the original list is unchanged after the call.
- `[]` → `[]`.

### `test_lists/test_case_quantifiers.py` — 3 functions

`any_`, `all_`, `none_`

- `any_`: `True` when at least one matches, `False` when none do.
- `all_`: `True` when every element matches, `False` when one does not.
- `none_`: `True` when nothing matches, `False` when something does.
- Empty-list vacuous truth is pinned explicitly: `any_([]) is False`, `all_([]) is True`,
  `none_([]) is True`.

### `test_dicts/test_case_lookup.py` — 2 functions

`first_`, `first_or_none_`

- The predicate is applied to **values**, not keys — asserted with a dict whose keys would give a
  different answer than its values.
- Both return a `(key, value)` tuple.
- `first_` raises `ValueError("No elements match the predicate.")` on no match and on `{}`.
- `first_or_none_` returns `None` in those cases.
- Both default to `lambda x: True` and then return the first inserted pair.

### `test_dicts/test_case_indexing.py` — 2 functions

`get_key_by_index_`, `get_key_value_by_index_`

- Index refers to insertion-order position; index `0` and a middle index both asserted.
- `get_key_value_by_index_` returns the `(key, value)` pair at that position.
- An index past the end raises `ValueError` matching exactly `"Index out of range."`.
- A negative index raises `ValueError` asserted **without** a message match, and carries a
  comment explaining why: `islice` rejects negative indices itself, so the `except StopIteration`
  branch never runs and the message comes from CPython rather than from `spinq`. This is a known
  message inconsistency, deliberately left as-is to keep this change additive; the tests document
  the current behaviour rather than the ideal one.
- `{}` with index `0` raises `ValueError("Index out of range.")`.

## Conventions

Follows the house style of the existing test packages:

- No `conftest.py` and no shared fixtures; each test constructs its own data inline.
- Explicit `# Arrange` / `# Act` / `# Assert` comment blocks (`# Act / Assert` where the two
  collapse, as with `pytest.raises`).
- `pytest.raises(ValueError, match=re.escape("..."))` wherever the message is part of the
  contract; bare `pytest.raises(Type)` where the message originates in CPython.
- Module-level named predicates (`def is_even(x: int) -> bool`) where a predicate is reused
  across tests; inline lambdas only for one-off use.
- Test names describe the behaviour, e.g. `test_first_on_empty_list_raises`.

## Verification

```
uv sync --all-groups
uv run pytest tests/test-spinq
uv run ruff format .
uv run ruff check . --fix
uv run bandit -r -c .bandit src tests sdlc
uv run pytest
```

Done when the full suite passes and both linters are clean.
